## Ledger rules

Use these states:

* OPEN-DOC: public sources disagree, omit a required detail, or are ambiguous.
* OPEN-HW: a controlled observation on the owner's board is required.
* OPEN-LEGAL: implementation provenance or redistribution needs a decision.
* IN-PROGRESS: a reproducer is being run or evidence is being analyzed.
* RESOLVED: evidence, result, implementation consequence and regression test
  are all linked in this file.
* OUT-OF-SCOPE: explicitly accepted as outside software-visible QEMU fidelity,
  with the reason and substitute/backend behavior recorded.

Resolution requires:

1. immutable evidence: repository commit and path, document revision/page, or
   hardware capture hash;
2. the observed value and conditions;
3. the QEMU behavior selected from that evidence;
4. a test that would fail if the behavior regresses.

Never close an item merely because Linux boots or a driver does not complain.

## Safe hardware workflow

The first hardware session is read-only and non-destructive:

1. Photograph both PCB faces, stickers, connector population and readable chip
   markings.  Record board revision and TH1520 marking.
2. Use a current-limited known-good supply and capture power-up UART from before
   reset release.  Do not attach expansion hardware initially.
3. Preserve the factory storage: record GPT/MBR, partition UUIDs, hashes,
   bootloader versions, DTBs, kernel config and firmware inventory before any
   update.
4. Boot a signed or owner-approved probe from removable media.  Read only
   documented side-effect-free CSRs and MMIO registers.
5. Add one controlled subsystem test at a time and preserve raw serial/logic
   analyzer/network/USB captures.
6. Do not write eFuses, key RAM, OTP, calibration storage, SPI flash or factory
   eMMC boot areas.  Do not enable undocumented clocks or power rails.

Potentially destructive boot-media writes, voltage changes, shorts/loopbacks,
thermal tests, security tests and fault injection require a separate explicit
authorization and a recovery procedure.

## Capture format

Store future captures outside the QEMU source tree under a date-stamped test
run directory, with a small tracked manifest containing:

* ledger ID and test program commit;
* PCB revision, SoC marking and board serial alias;
* boot image and every binary/DTB hash;
* power supply, UART settings and attached hardware;
* exact steps and expected safe side effects;
* raw capture filenames and SHA-256 hashes;
* parsed result, QEMU comparison and pass/fail;
* follow-up issue/test/commit.

Do not commit secrets, unique keys, MAC addresses, Wi-Fi credentials, board
serials, proprietary firmware or copyrighted manuals.  Redact public reports
while retaining a private evidence hash.

## GMAC-001 Type-2 receive-status checkpoint

Local checkpoint ``46df230d5d`` enables Type-2 receive status only for the
TH1520 instances; the reusable DWC GMAC property's default remains off so the
existing NPCM machines retain their descriptor contract.  When the advertised
Type-2 and enhanced-descriptor features, ``MAC_CONFIG.IPC`` and
``DMA_BUS_MODE.ATDS`` are all active, QEMU classifies the original backend
frame before adding the synthesized FCS.  It validates bounded IPv4/IPv6 and
TCP/UDP/ICMP checksums, unwraps one ``0x8100`` C-VLAN tag or one ``0x88a8``
S-VLAN tag only when ``VLAN_TAG.ESVL`` is set, and reports documented
fragment/security/routing/unsupported cases as bypassed.  Only the terminal
descriptor receives little-endian RDES4, RDES0.ESA and checksum-derived ES;
extension words 5-7 are preserved.  The static machine property adds no
migrated field.  Existing register and guest-memory state is sufficient for
the focused migration test to produce the same RDES4 result after resume.

The implementation deliberately does not model checksum-error frame dropping.
Hardware enables the checksum engine with IPC independently of ATDS, whereas
ATDS only makes extended descriptor words valid.  This bounded checkpoint
therefore treats ATDS-off as “no observable RDES4/ESA contract”; it does not
claim that the hidden hardware engine is disabled.  DT/FEF/RSF and receive
threshold interactions must be modeled together later: in cut-through mode an
error discovered after a frame start crosses the read threshold can no longer
be filtered.  A blanket drop would be incorrect.

The normal gate passes 109/109 board tests, dependency-minimal and ASan/UBSan

The Type-2 matrix covers valid IPv4/UDP, bad IPv4 header, bad UDP, valid

S-VLAN with ESVL clear/set, truncated VLAN and IPC/ATDS-disabled cases.  A
separate split-ring case proves that status appears only on the final
descriptor.  These are deterministic emulator contracts, not owner-board
measurements.

* exact ESA/RDES4 results for IEEE 802.3, runt, truncated Ethernet/VLAN and

* double VLAN and alternate TPIDs, which the current single-tag model

## GMAC-001 transmit-checksum checkpoint

Local checkpoint ``f441cf709f`` replaces the shared DWC GMAC model's
IPv4-only checksum shortcut with a bounded transmit Checksum Offload Engine
contract.  The generic behavior is grounded in the
[Synopsys Ethernet MAC checksum bulletin](https://www.synopsys.com/dw/dwtb.php?a=ethernet_mac)
and the descriptor and error semantics published in the
[TI MSP432E4 technical reference manual](https://www.ti.com/lit/ug/slau723a/slau723a.pdf).
The TH1520 feature description and physical boot log advertise TX checksum
offload, while pinned Linux detects TXCOESEL, selects store-and-forward mode,
programs CIC3 on a frame's first normal or enhanced descriptor, and consumes
the enhanced IHE/IPE/ES status.  These sources define the local implementation
contract; they do not prove the owner's silicon behavior.

Insertion requires the advertised TXCOESEL feature and
``DMA_CONTROL.TSF``.  CIC is captured from the first descriptor and applied
when the terminal descriptor closes the gathered frame: CIC0 bypasses, CIC1
inserts only the IPv4 header checksum, CIC2 includes the transport checksum
field as the guest-supplied pseudo-header seed, and CIC3 calculates the full
pseudo-header.  The bounded parser handles IPv4 options, IPv6 hop-by-hop and
destination options, TCP, UDP, ICMP and ICMPv6 through one ``0x8100`` C-VLAN
or one ``0x88a8`` S-VLAN when ESVL is enabled.  Fragment, routing, mobility,
AH, ESP and unsupported payloads bypass payload insertion after bounded header
validation.  Only a computed UDP zero is mapped to ``0xffff``.

QEMU changes the host-side gathered frame sent to the network backend, not
the guest's DMA source buffers.  Bytes beyond the IP-declared payload are
transmitted unchanged as stuff and excluded from the transport checksum.  If
the supplied transport bytes end before the IP-declared payload, QEMU reports
IPE and still inserts over the available bytes using the declared pseudo
length.  A malformed IP header reports IHE.  Both statuses are cleared on
every completed descriptor and written only on the terminal descriptor;
enhanced descriptors include them in ES, while the normal descriptor's ES
definition does not.  TX assembly remains synchronous, so the checkpoint adds
no migrated state.

One BeagleV qtest registration uses an independent checksum oracle for 18
cases covering all four CIC values, both IP versions, all supported transport
protocols, header options, C-/S-VLAN, split descriptors and buffers, TSF
bypass, UDP zero, trailing stuff, a deliberately mismatched UDP length, short
payloads, malformed headers, stale-status clearing and guest-buffer
preservation.  The normal board gate passes 109/109; dependency-minimal and
ASan/UBSan each pass 108/108.  The reusable NPCM GMAC suite passes 7/7 and
adds one normal-descriptor CIC3 IPv4/UDP compatibility case.  That single case
does not claim comprehensive NPCM compatibility or enhanced-status coverage.

Unlike TH1520's opt-in Type-2 receive property, this transmit behavior affects
every shared-core instance that advertises TXCOESEL.  The old generic helper
incidentally traversed some ``0x88a8`` and stacked ``0x88a8``/``0x8100``
frames.  The bounded model deliberately supports only one tag and requires
ESVL for an S-VLAN; other forms bypass insertion.  Treat that as an explicit
compatibility boundary until a represented machine supplies authoritative
synthesis evidence.

The following questions remain open for physical comparison:

* the exact hardware-feature word and TX FIFO depth, PBL boundary, full-FIFO
  failure mode, recovery of following frames and threshold-mode behavior;
* CIC2 seed semantics and CIC1 on IPv6, especially with extension headers;
* normal-versus-enhanced IHE/IPE/ES results, descriptor writeback order and
  partial state after DMA or bus faults;
* malformed IPv4/IPv6 lengths and actual transmitted bytes, UDP-length
  mismatch, padding/stuff boundaries, jumbograms and computed-zero checksums;
* fragments, IPv6 routing/security/mobility extensions, alternate or stacked
  VLANs, VLAN insertion and checksum-engine composition;
* composition with FCS, PTP timestamp descriptors, MMC, pause/flow control,
  underflow and carrier/collision status; and
* sustained Linux IPv4/IPv6 TCP/UDP/ICMP traffic on each physically routable
  instance, with complete before/after descriptor and packet captures.

Preserve the input DMA buffers, complete transmitted frame, descriptor words,
MAC/DMA registers, IRQ order, clock/reset state and board/silicon revision for
each physical case before changing this deterministic QEMU policy.

## GMAC-001 receive-interrupt-watchdog checkpoint

Local checkpoint ``1369cec4d9`` implements the DMA Receive Interrupt Watchdog
Timer register at offset ``0x1024``.  The publicly hosted TH1520 Peripheral
Interface User Manual, section 1.6.3.10, describes bits 31:8 as read-only/reset
zero and RIWT[7:0] as read/write/reset zero.  A nonzero value starts after RX
DMA transfers a frame whose terminal descriptor has DIC set; each unit is 256
system-clock cycles.  Expiry sets RI and stops.  A later DIC-clear completion
raises RI and resets/stops the watchdog.  DMA STATUS.RWT is separately
documented as receive-frame truncation while a frame is arriving and is not
the interrupt-coalescing expiry bit.  The manual's restrictive markings keep
``DOC-001`` open.

The reusable DWC GMAC property defaults the RIWT conversion clock to zero so
existing NPCM machines keep their prior contract.  TH1520 supplies a fixed
500 MHz reset/reference-rate assumption; Linux's default ``RIWT=0xa0`` is
therefore exactly 81,920 ns.  A DIC-suppressed terminal completion arms a
one-shot only while RI is clear and does not reload an already pending timer.
Expiry sets RI and recomputes NIS/IRQ.  A DIC-clear completion cancels the
timer and raises RI immediately; a zero write or device reset also cancels it.
A nonzero rewrite affects the next arm rather than restarting the current
deadline.

The focused ``rx-interrupt-watchdog`` and ``rx-watchdog-migration`` qtests pass
1/1 each, and the complete GMAC group passes 12/12.  They cover upper-bit
masking, 81,919 ns quiet plus one-nanosecond expiry, RI/NIS and PLIC source 66,
asserted and armed system reset, zero-write cancellation, a later non-DIC
completion, and current-v2 migration halfway through the deadline.  The
destination remains quiet through remaining time minus one nanosecond and
expires on the next.  Whole-machine and legacy-device migration regressions
also pass.  A deliberate 256-to-257 cycle-scale mutation fails at the exact
deadline assertion; the restored source passes.  VMState version 2 migrates
the timer; pre-version-2 streams retain only the masked low register byte and
load unarmed because no deadline exists.

Four clean pinned-Linux runs pass DHCP, 3/3 gateway pings and a 1 MiB HTTP
download with SHA-256
``fbbab289f7f94b25736c58be46a994c441fd02552cc6022352e3d86d2fab7c83``:
``run-9uieaud1`` and ``run-tk0021lq`` are the normal one-/four-hart cases;
``run-ev_lpw_x`` and ``run-xc7n_lma`` repeat them with the dependency-minimal
build.  Retained ``run-53c1sfu1`` is a contention/timing-sensitive Linux
masked-RI race, not a reason to change QEMU's documented device contract.  In
that schedule RIWT expires while RIE is masked; an unrelated TX interrupt
causes the ISR to W1C-clear RI without scheduling RX, leaving three completed
descriptors temporarily stranded and the 1 MiB transfer stalled.

The fixed 500 MHz conversion is not a dynamic clock model or a measurement of
the owner's silicon.  Hardware comparison must establish the actual rate on
both cores, DIC start/reload behavior, RI/NIS W1C and re-arm ordering, zero and
nonzero writes while armed, DMA stop/disable, clock-gate and rate changes,
cold/warm/AP/subsystem reset behavior and expiry-to-PLIC latency.  Focused QEMU
tests already isolate RWT/AIS absence, independent RI/NIS clears, repeated DIC
nonreload and nonzero-rewrite nonrestart.  Soft/AP reset and crafted pre-v2
nonzero-RIWT loads remain useful follow-up coverage.
